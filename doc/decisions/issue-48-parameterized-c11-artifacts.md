# Issue #48 — Emit and build parameterized strict-C11 programs

- **Issue:** https://github.com/tuncbahreadingmaterial-ops/Faraweave/issues/48
- **File status:** Active append-only decision record

## 2026-07-25 — Decode process text into fixed typed slots before evaluation

- **Context:** Issue #45 made typed lowering independent of concrete values, Issue #46 added indexed scalar parameter references, and Issue #47 defined the runner's exact ASCII grammar and raw-text-free `ArgumentError` record. Generated and native artifacts still rejected every parameter header. The artifact boundary must validate `argc` before `argv` indexing, produce the runner-equivalent binary64 value on supported C11 libraries, begin evaluation resources only after all text is accepted, and retain the existing typed lowering, admission charges, failure order, cleanup, and atomic root publication without adding dynamic typing or parameter specialization.
- **Decision:** Every generated program now exposes hosted `int main(int argc, char **argv)` and a generated count-first adapter. `argc <= 1` supplies zero arguments without subtraction or indexing. Before resolution, lowering, or C table emission, an allocation-free metadata preflight checks declaration counts, zero- and one-based indices, the extra-argument position, source coordinates, parameter-name termination, C unsigned-literal representation, hosted count conversion, and every generated parameter-table byte product; refusal is `ResourceError(size_overflow)` at the complete parameter header. The adapter checks the exact required count, forces the standard process numeric locale to `"C"`, and decodes declarations in position order into a fixed static array of scalar `FaraweaveValue` slots. Bool and Int use explicit ASCII grammar and checked integer accumulation. Double accepts only the specified finite grammar and exact `inf`, `-inf`, and canonical `nan`; after lexical validation it uses standard C11 `strtod`, rejects partial or non-finite finite conversions, and preserves the returned binary64 bits, including subnormals and signed underflow zero. The supported Linux, Windows, and macOS C libraries are required to provide correctly rounded conversion and are checked by the target-native differential boundary corpus. Generated argument records contain only emitted declaration metadata and numeric counts; raw `argv` bytes are never formatting arguments. Parameter-reference lowering copies one already-typed scalar slot into its flat node slot with no allocation. Only after binding succeeds does `faraweave_execute` create `FaraweaveResources` and run the existing selected implementations, shape checks, admissions, last-use releases, failure snapshot, and root publication.
- **Alternatives considered:** Embedding build-time values would specialize artifacts and make bytes input-dependent. Calling the Faraweave evaluator or adding runtime overload lookup would duplicate the language runtime and reintroduce dynamic selection. `sscanf`, `atoi`, `strtol`, or unvalidated `strtod` would accept prefixes or locale-sensitive extensions and provide the wrong error boundary. `strtod_l`, `_strtod_l`, `newlocale`, Windows wide entry points, or platform-specific parser branches would violate strict portable C11 scope. A fixed token-length big-integer parser would add an arbitrary host-visible cap; an allocating arbitrary-precision parser would enlarge cleanup and cost surfaces for no additional supported-toolchain result. Dynamically allocated parameter values or reference counting would obscure ownership without providing a language capability.
- **Rationale:** Declaration types and slot indexes are already authoritative in the flat lowering, so a boundary-only decoder and direct slot copy are the smallest coherent extension. Lexical prevalidation closes the grammar independently of the C library, while the standard C locale prevents process locale from changing decimal meaning. Supported-library differential cases at ties, adjacent binary64 results, extrema, subnormals, signed zero, infinities, NaN, and overflow make the remaining conversion portability assumption explicit and measurable. Fixed scalar slots make binding cost and ownership visible: zero Faraweave work units, zero live bytes, and zero dynamic allocations.
- **Consequences or follow-up:** Zero-parameter and header-absent artifacts now reject extra process arguments with the same structured-equivalent record as the runner. Statically valid literal-guaranteed dynamic failures emit and build successfully and fail only when invoked. Generated C grows one reusable ASCII decoder and declaration metadata, but no parameter value appears in emitted bytes and no runtime type/signature selection is introduced. Raw narrow `argv` remains the supported artifact boundary; strings, vectors, named/default/variadic inputs, Windows wide entry points, and a language-level Unicode claim remain non-goals. Faraweave deliberately differs from Anka by keeping the public parameter contract, structured process failures, explicit resource admission, and flat typed slots in Faraweave rather than inheriting Anka's concrete evaluator or artifact behavior.
- **Validation/evidence:** `PARG-012-EMIT-C parameter slots are value independent` checks repeated identical emission, fixed slots, hosted entry, selected typed implementations, and absence of nonstandard locale APIs. `cli.parameterized_c_artifacts` emits twice, byte-compares output, compiles generated C with the target compiler's strict C11 warnings-as-errors mode, builds a native artifact through `faraweave build`, and compares runner/emitted/native results for Bool, Int extrema, promotion, parameter-driven `iota`, binary64 ties and adjacent values, min subnormal, signed underflow zero, maximum finite, infinities, NaN, missing/extra/malformed/partial/out-of-range/wrong-visible-type/hostile tokens, zero parameters, deferred literal failure, dynamic shape failure, and multi-root atomicity. The bounded-profile and allocation-injection paths reuse the production lowering/runtime coverage in `public.api_resource_matrix`; parameter binding itself is checked to precede resource creation and to emit only scalar copies. Target-native Release, strict, sanitizer, and isolated QA evidence is completed by the issue workflow before acceptance.
